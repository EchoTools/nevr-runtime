# Quest networking implementation: shared source, measured callbacks

Date: 2026-10-06
Status: Astra approved preparation tranche 0 and bounded implementation tranches 1a and 1b; later tranches require separate review

## Scope and existing baseline

Quest and PCVR clients use the same game-facing EVR behavior. The work is to reuse the PCVR policy, login data, wire handling and session routing in both builds, with narrow PE/ELF, game ABI and OS adapters. The first seam is the **same logical config-string lookup** that PCVR already hooks; an Android HTTP request hook is not yet established. No Quest-specific framing, protobuf matchmaking frames, local Nakama, game configuration mutation, routine game launch, APK install, headset, or production-service check belongs to these tranches.

Implementation evidence was gathered against source HEAD `918d4c9`; later commits changed documentation only. Tranche 1 of the older plan was completed in `4b11c98`: `src/runtime/compat/login_profile.cpp` is compiled by the Windows runtime, `test_behavioral`, and Android `nevr_quest_login_profile` (`src/runtime/CMakeLists.txt:33,588`; `src/quest/CMakeLists.txt:30-35`). The Android profile target is not linked into the sentinel. The current sentinel is `entry.cpp` plus `got_hook.cpp`; `HookImport` has no detach or duplicate guard and ignores the last `mprotect` result (`src/quest/sentinel/CMakeLists.txt:5-9`, `got_hook.cpp:127-136`). The Android preset already uses the Quest-local vcpkg manifest, `arm64-android`, NDK chainload and API 26 (`src/quest/CMakePresets.json:7-17`); the older design's contrary setup step is stale.

The present host has `adb` at `/opt/android-sdk/platform-tools/adb` and `qemu-system-aarch64`, but no `emulator` executable or arm64 Android system image was found in `/opt/android-sdk` or `/home/andrew/Android/Sdk`; the latter contains an x86_64 Android Wear image. Thus an arm64 Bionic runner is **not currently available**. Provisioning it is a prerequisite, not an assumed test result. Plan capacity for one isolated VM runner with at least 4 GiB RAM and 10 GiB free disk (planning allocation, not a measured package size); measure actual image size, boot time and test duration before setting CI deadlines. Prefer an arm64 Android VM image at API 26 or newer; the existing x86_64 Wear image and Linux `qemu-aarch64` do not satisfy Bionic/arm64 loader tests. Preflight must record ABI/API, Bionic linker/libc, and successful execution of an NDK arm64 probe DSO plus `mprotect`/`dlopen` smoke. Do not install packages or launch a VM in this design pass.

`docs/design/2026-10-06-quest-testing-regime.md` supplies the offline test gates. This plan supersedes the implementation sequence and routine-run assumptions in `docs/design/2026-10-06-quest-networking-port.md:59-67,103-136`; its binary and EVR source evidence remains useful.

### Tranche 1b contract and acceptance

**Current behavior to preserve.** `service_config.cpp:195-205` interns by value under a mutex and returns a `std::set<std::string>::c_str()`; its seven callers at lines 211-278 include flat/CSV lookup, service host, redirect, game default, relay and game-native JSON. The last can contain `nevr_server_key` (`:271-278`). The set is never erased during normal use, but its function-static destructor invalidates returned pointers if the runtime unloads; the comment's process-lifetime guarantee is therefore stronger than the implementation. `config.cpp:443-471` retains the original result pointer when no redirect is chosen, and `:475-503` uses pointer identity as a missing-key signal. No 1b path may intern an unchanged game result or convert a missing key's original fallback pointer into an equal-content replacement.

**API, failure and owner.** Extract one shared `InternStableCStr(std::string_view) -> InternResult{status, pointer}` operation; `status` distinguishes success, embedded NUL, quota and allocation failure. The existing seven `const char*` accessors cannot represent this error: `nullptr` already means absent and is treated as a fallback by `config.cpp:337-338,467`, `ws_bridge.cpp:951-955,1037-1038`, and the `moduleCtx.config_get = &NevrCfgGetFlat` consumer in `boot.cpp:232`. Therefore each C accessor calls one `InternOrTerminate` boundary: a valid absent/no-redirect input retains its current `nullptr` result, while **any attempted intern that fails logs only the error kind and counts, calls `ForceFatalExit(1)`, then `std::abort()` if it unexpectedly returns**. No caller receives null on a storage error. This policy applies to `NevrCfgGetFlat`, `NevrCfgGetFlatCsv`, `NevrCfgServiceHost`, `NevrCfgRedirect`, `NevrGameNativeDefault`, `NevrCfgAutoRelay`, and `NevrCfgGameNativeConfigJson`. `NevrCfgServiceHost` preserves its present contract: on absent host, set `*outSource=2` when nonnull and return null; on present host, publish source 0/1 only after successful interning; storage error terminates without returning. Do not use `ServerFatal` because it returns on clients (`crash_recovery.cpp:1186-1203`). Catch `const std::exception&` around each exported accessor's lookup/build/intern body and take the same redacted terminal path; no C++ exception crosses the C/game/module callback ABI. Tranche 1c must provide the Android terminal/logging adapter before using the pool from a game callback. This deliberately fail-stops on exhaustion instead of changing an authenticated route or disabling an optional feature as though it were absent.

The smallest intended owner is the existing mutex/set pool allocated once on the heap, never destroyed. The set still owns deduplicated `std::string` nodes; no C++ static/DSO destructor clears them. This depends on the process C++ allocator retaining allocations after module unload, so production-source Wine and later Bionic unload fixtures must prove it. If either allocator unloads its heap, stop and separately review a process-owned allocation backend. Published bytes are immutable and NUL terminated. Reject embedded NUL rather than publish a truncated C string. Lock through lookup, allocation and publication so equal concurrent values return one pointer; publish only after the full copy and terminator exist. `config.cpp:443-471` keeps the original game pointer when redirect is absent; interning cannot replace an unchanged pointer or turn a missing-key default pointer into an equal-content replacement.

**Measured source inputs and proposed bound.** Read-only inspection of `src/runtime/tests/test_service_map.cpp:42-70`'s `kFullYaml` yields 20 scalar values, 19 distinct, 27 maximum UTF-8 bytes and 296 total distinct-value bytes; some scalars (such as `version`) are not actually interned, so this is a fixture upper count, not a measured pool occupancy. Its four public `EmbeddedDefaults()` values at `:443-448` total 90 bytes and peak at 28 bytes. The game-native JSON test at `:540-579` uses `https://game.example:7350` and `the-server-key`; applying the field layout in `service_map.cpp:162-202` with compact, sorted-key JSON yields **234 bytes** (illustrative source calculation; verify against `nlohmann::json::dump()` in 1b tests). Applying the four-default fixture's HTTP URI and key yields 241 bytes. The escaping fixture's five-byte key `a\"b\\c` expands to a 224-byte JSON document; include a larger escaped/NUL input in boundary tests. Actual configure-time defaults come from private environment/`.env` into a build-tree header (`cmake/nevr_builtin_defaults.cmake`, `.h.in`), so their values and production maxima are not established by public fixtures; do not read or print them for this design. These observations justify only test coverage, not a production maximum. Propose a policy of at most 1,024 distinct strings, 1 MiB of UTF-8 bytes per string and 16 MiB of live string bytes **per pool generation**, with checked arithmetic, NUL terminators included in allocation accounting, and separately estimated set-node/index overhead. Before implementation, review valid maximum sizes and JSON expansion against public schema/fixture ranges and a synthetic near-limit escaped value; do not claim the proposed limits cover unknown private values. Duplicates consume no new quota. Exhaustion/allocator failure takes the terminal path above; never evict an escaped value.

The leaked pool's quota resets if the DSO unloads and reloads: it is **not a process-wide memory cap**. A second load can create another leaked generation. Tranche 1b supports one module generation only and may demonstrate a single unload for pointer-lifetime proof; repeated load/unload publication is unsupported. Before activating a game hook, tranche 1e must establish that the runtime/module cannot reload after publishing a pointer or add a separately reviewed process-owned registry/cumulative bound. Do not describe the per-generation policy as a process bound or claim that source-only evidence proves its runtime frequency. This shared pool also retains server-key-bearing JSON and any other secret-bearing configured string through unload; do not log values or dump its pages. Zeroing escaped bytes on detach would violate borrowed-pointer lifetime and is outside 1b.

**Files and tests for the 1b commit.** Add `src/runtime/lifecycle/stable_string_pool.{h,cpp}`; replace only the local `InternCStr` body/calls in `service_config.cpp` and update `service_config.h`'s lifetime/error contract. Add that shared source to `src/runtime/CMakeLists.txt`'s `nevr_runtime` and direct-source test targets and to `src/quest/CMakeLists.txt`'s Android target/test executable; extend `tools/tests/test_quest_shared_redirect_sources.py` to reject source-list drift. Supply injected in-memory config/default providers to the direct-accessor tests; death cases must not trigger real config-file discovery or environment reads. Tests assert same-value pointer identity across repeated and simultaneous calls, distinct-value stability, empty string, embedded NUL rejection, each quota boundary including NUL/accounting, injected allocation failure, no partial publication or secret-bearing diagnostics. Start `NevrCfgServiceHost`'s `outSource` at 0 and 1 in absent-host cases and assert it becomes 2; allow a null `outSource`. Subprocess death tests must invoke **each of the seven C accessors** on an injected intern failure, including `NevrCfgGetFlat` through `moduleCtx.config_get`, and show that no null/absence fallback executes; test exception containment on the same boundary. Test the existing Windows original-pointer pass-through when no redirect is selected and a replacement through two lookups and later read.

The Wine lifetime fixture must compile the **same production pool source and allocator/link flags** into a DSO, export a pointer, quiesce all calling threads, release every extra DSO handle, call `FreeLibrary`, and confirm actual module removal with a loader/module query before reading that pointer. A destructible function-static pool control must demonstrably fail a lifetime check on unload; reading old bytes alone is insufficient because freed memory may remain unchanged. Use an allocation-owner/destructor sentinel or guarded reuse to make that control deterministic. The analogous Bionic `dlopen`/`dlclose` fixture must confirm no `NODELETE`/remaining reference before claiming unload, then read the pointer and run concurrent lookup before quiescence. If actual unload or red-control invalidation cannot be proved, lifetime acceptance is blocked. NDK compile/link and ELF checks are the current Android exit; Bionic execution waits for an arm64 runner. No game process, service, APK install or hook is part of 1b.

**Open limit.** `std::set`'s present lifetime during normal Windows operation does not measure how long the game actually retains its pointer. A never-destroyed pool is deliberately conservative; the review must accept its secret-residency cost, fail-stop capacity policy and unsupported reload behavior. Pool survival after unload is a **test gate**, not inferred from source. Tranche 1c still owns typed Quest callback/fallback assertions, and 1e still owns production hook detach and slot restoration; a 1b DSO fixture proves storage lifetime only.

## Promotion and evidence gates

1. **No guessed ABI:** opaque Quest CJson layout and C-string return are handled without reading or modifying game fields; a typed declaration follows callsite registers and return flow. Any need to inspect game fields, any different flag width or any hidden ABI parameter requires new exact-binary evidence. Test an exact-ELF caller path under arm64 Bionic if static evidence leaves return ownership or call entry ambiguous. A synthetic callback alone is insufficient.
2. **No unsafe hook lifecycle:** fixture hash/build ID and relocation must match before write. One handle owns one module slot and its captured, actually resolved pointer; its address need not equal the owning ELF's local definition. Confirm Bionic lazy binding does not recurse; check `mprotect` restore and exact pointer restoration on production detach. Retained replacement strings survive detach/DSO unload because storage is intentionally process-lifetime. Do not turn on the game hook if thread/frequency, loader timing, original pointer stability or teardown safety affects correctness and remains unmeasured.
3. **Same source, no drift:** Windows and Quest CMake targets name the same portable `service_redirect`, stable pool, login profile, eventual codec and router files. Each new portable source has direct Windows and Android test linkage; Win32/MinHook, Bionic/GOT, file search, TLS and game-object types remain adapters. Existing `src/core/hooking.h:35-109` has reusable publish-before-enable behavior but Windows headers; extract only its portable lifecycle contract when doing so reduces duplication, keeping MinHook and GOT mechanics separate.
4. **Offline acceptance only here:** use exact-build fixture tests, MinGW/Wine unit tests, NDK artifact checks and a *provisioned* arm64 Bionic VM for OS-specific behavior. The VM is unavailable today, so those checks are blocked until its preflight passes. No routine device installation, game process, production account, config edit, local Nakama, or production log is required or authorized by this plan. A later release qualification for exact installed APK identity and actual game invocation is separate. No implementation, build or test was performed in this design pass.

**Process gate before a runtime-code commit:** `AGENTS.md` §“System test after every commit” requires `./launch-client.sh` against production after runtime commits, while the current user scope bars routine game/runtime/service checks. This document cannot amend or waive `AGENTS.md`. Offline preparation can finish, but before Luna makes a runtime-code commit the owner must correct `AGENTS.md` or explicitly settle which current rule governs.
